# 睡了吗

听书睡着后，替你按下暂停。

手机放在枕边播有声书，人先睡着了 —— 播放器还在跑，第二天醒来不知道听到哪一集。
这个小工具会在你**连续 N 分钟没碰音量键**之后，暂停掉正在播放的音频，并记下书名和播放位置；
如果你只是翻身随手按了一下音量键，计时会重来。暂停之后的 M 分钟内按音量键，还能原样续播。

## 功能

- **无操作检测**：音量键、电源键灭屏、解锁屏幕都算「你还醒着」，不需要一直盯着屏幕
- **两级暂停**：优先直接控制播放器的 MediaSession（能拿到书名和进度），拿不到再抢音频焦点兜底
- **进度记录**：暂停瞬间记一次，播放过程中每 30 秒落盘一次快照，进程被杀也不丢
- **恢复窗口**：暂停后 M 分钟内按音量键自动续播，超时就让它安静停着
- **耳机断连触发**（可选）：摘下耳机、蓝牙没电断开，比音量键更早给出信号
- **随手可控**：快捷设置磁贴、桌面长按快捷方式、通知栏「我还醒着 / 立即暂停 / 续播」
- **记录页**：近 7 天次数、平均入睡时刻、按日期分组，点一下直接跳回那个 App 接着听
- 深色界面，睡前看不刺眼

## 安装

到 [Releases](../../releases) 下载最新的 `apk`，传到手机上安装即可（需要允许安装未知来源）。

支持 **Android 8.0（API 26）及以上**。

## 使用

1. 打开应用，按引导开启**通知使用权**和**忽略电池优化**
2. 先去听书 App 播起来，再回到「睡了吗」点**开始守护**
3. 睡着后 N 分钟没有音量键操作，音频自动暂停，进度自动记下
4. 早上打开应用，或看通知，就知道昨晚听到哪儿了

想快速验证？把「无操作多久算睡着」调到 1 分钟，点开始，然后什么都不按。

## 工作原理

### 1. 怎么知道你还醒着

普通应用拿不到全局按键事件，所以两条路都是「曲线救国」。

**音量键** —— 按下去一定会改系统里的 `volume_*` 设置值，用 `ContentObserver` 观察这些 key，
就等价于观察到了按键。熄屏、后台都能收到。
代价是音量已经在 0 或最大时再按不产生变化，会漏判，所以建议把媒体音量留在 40%–70%。

**电源键** —— `KEYCODE_POWER` 同样不交给第三方，但它带来的状态变化是广播出来的：

| 事件 | 算不算清醒 | 说明 |
|---|---|---|
| `ACTION_SCREEN_OFF` | 算 | 按电源键灭屏，或屏幕超时自动熄灭，两种都说明人还醒着 |
| `ACTION_USER_PRESENT` | 算 | 亮屏后解锁，误判率极低 |
| `ACTION_SCREEN_ON` 且未锁屏 | 算 | 抬起唤醒这类小动作 |
| `ACTION_SCREEN_ON` 但停在锁屏界面 | **不算** | 多半是来通知时屏幕闪一下，人可能睡得很沉 |

这里有一条刻意的不对称：**暂停之后只有音量键能续播，电源键不续播**。
半夜醒来按一下电源键看时间，不应该把有声书放出来。

未来还可以接入无障碍服务做 100% 按键捕获。

### 2. 怎么暂停别的 App

安卓没有「暂停其他应用」的 API，所以做了两级降级：

| 级别 | 手段 | 能拿到什么 | 恢复方式 |
|---|---|---|---|
| 一 | 通过通知使用权拿到其他 App 的 `MediaController`，直接 `transportControls.pause()` | 书名、章节、播放位置 | `play()` 精准续播 |
| 二 | 请求 `AUDIOFOCUS_GAIN`，守规矩的播放器自己 pause | 只知道「有人在播」 | `abandonAudioFocus` 后对方自动 resume |

服务启动时还会挂一个 `STATE_PAUSED` 的空 `MediaSession`，目的是把音量键**钉在媒体流上** ——
否则对方暂停后系统会认为「没有媒体在播」，音量键转去调铃声，监听就失效了。

### 3. 为什么恢复窗口过了也不退出

焦点是通过「持有」来生效的。进程一退，焦点自动释放，对方的播放器会自己 resume —— 等于白暂停。
所以超时之后服务会保持前台（已释放 wakelock，耗电可忽略），让音频一直停着，等你早上自己结束。

## 想要什么功能？

这一版只做了「音量键 + 时间」这一条判断路径，但睡眠这件事显然不止一种信号。
下面这些是我自己想到、还没做的方向。欢迎投票、补充，或者直接说「这个没用」：

### 更可靠的睡眠信号

- **充电即睡前**：插上充电器开始计时，拔掉就取消（最容易做，也最省电）
- **静止检测**：加速度计连续 N 分钟无位移。躺着不动≈睡了，但听书时手机本来也常常是静止的，可能误判
- **屏幕朝下 / 光线骤降**：用距离传感器和光线传感器判断手机是不是被扣在枕边
- **耳机断开**（已支持，默认开启）
- **手环 / 手表心率**：接 Health Connect 或厂商 SDK，心率落到静息区间才认为睡着
- **鼾声检测**：麦克风采样。隐私敏感，但如果只在本机算声学特征、不上传，也不是不能考虑
- **系统睡眠模式**：监听勿扰、睡眠模式、数字健康的状态变化
- **作息时间窗**：只在 23:00–06:00 之间才启用守护，白天按音量键不会误触发

### 睡着之后还能做什么

- **自动关屏 / 锁屏**：需要设备管理权限，代价比较大
- **自动开勿扰**，免得半夜被消息震醒
- **降低亮度、关闭抬手亮屏**
- **记一句睡前笔记**：把「昨晚听到《XX》第 12 章 34:56」写进日记 App，或发到自己的微信 / 邮箱
- **顺手设个闹钟**：按第二天的日程推荐起床时间
- **断开蓝牙**，省耳机那点电
- **连续多天统计**：一周里哪几天最容易听着听着睡着

### 其它

- 桌面小组件（Glance）
- 记录导出 CSV / Markdown
- 浅色主题、英文界面
- 多设备同步（大概率不做，想保持纯本地）

有想法的直接开 Issue，说清楚「什么场景下希望它做什么」，比只说功能名有用得多。

## 兼容性

当前支持 **Android 8.0（API 26）及以上**。

- 8.0 是这条技术路线的天然下限：`AudioFocusRequest`、`NotificationChannel`、`VibrationEffect` 都是 API 26 才引入的，
  再往下就得为它们各写一套兼容分支
- Android 8.x / 9 上，快捷设置磁贴不会显示状态副标题（`Tile.subtitle` 是 API 29 才有的）
- 各家 ROM 对后台存活、通知权限、音频焦点的收紧程度不一样，实际表现可能有差异

**如果你的设备跑不起来，哪怕只有你一个人在用它，也请开个 Issue 告诉我机型和系统版本。**
我会尽力支持 —— 有时候只是补一个版本判断，有时候要换一套实现，但至少值得先看一眼。

## iOS 呢？

做不了。不是工作量的问题，是系统不给能力：

- **第三方 App 无法暂停别的 App 的音频**。iOS 没有跨应用音频控制接口，`AVAudioSession` 只管自己
- **无法监听音量键**。`MPVolumeView` 只能改音量，拿不到按键事件
- 后台长时间驻留同样受限

所以「自动帮你暂停有声书」这件事，在 iPhone 上只有系统自己能做 ——
「时钟 → 计时器 → 计时结束时：停止播放」就是苹果留给自己的特权。

勉强能模拟的方案是用「快捷指令」的个人自动化：

> 连接充电器 → 等待 30 分钟 → 暂停播放

但它只认「插上充电」这一个信号，并不知道你是不是真的睡着了。

如果哪天 iOS 开放了相关能力，这里会第一时间跟进。

## 已知限制

- **通知使用权是硬门槛**。没开也能用，但只能抢音频焦点：暂停成功率下降，也记不住进度
- **纯焦点模式拿不到播放位置**。界面上会明确写「这次没记下进度」，不会编一个假数据
- **暂停后电源键不会续播**：刻意设计，免得半夜看时间被声音吵到；要续播请按音量键或点通知
- **音量键盲区**：音量在 0 或最大时再按无变化，会漏判
- **国产 ROM 保活**要手动设：应用启动管理里关掉「自动管理」、最近任务下拉加锁
- 未在大量机型上长期验证，音量键监听在不同 ROM 上的表现可能有差异 —— 欢迎反馈实际结果

## 构建

```bash
./gradlew assembleDebug
```

需要 JDK 17 和 Android SDK 35。产物在 `app/build/outputs/apk/debug/`。

技术栈：Kotlin + Jetpack Compose + DataStore，无第三方 SDK，无网络权限，数据全部留在本机。
